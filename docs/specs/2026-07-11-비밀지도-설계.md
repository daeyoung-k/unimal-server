# 우리지도(폐쇄형 공유 지도) — 백엔드 설계

> 작성일: 2026-07-11 · 상태: 초안(확정 결정 반영) · 관련: [Flutter UX 스펙](../../../..//unimal_flutter/docs/specs/2026-07-11-비밀지도-UX.md)

> 노출명 확정: **우리지도** (2026-07-11, 구 작업명 "비밀지도"). 문서 파일명과 코드 식별자(SharedMap)는 유지 — UI 노출 문자열에만 적용.

## 1. 배경 / 왜

- 공개 지도 피드는 콜드스타트 문제가 크다(내 동네에 글이 없으면 앱이 비어 보임). 폐쇄형 지도는 친구 2~3명만 있어도 첫날부터 가치가 생긴다.
- 기존 "내지도"의 멀티플레이어 확장이다. 새 시스템이 아니라 **게시글에 스코프(어느 지도 소속인지)를 부여하는 작업**.
- 예시 유스케이스: 길고양이 급식소 공유 지도(집사 전용), 러닝 크루 코스 지도, 방탈출 모임 지도, 소품샵 투어 지도.

## 2. 확정된 결정

| 항목 | 결정 |
|------|------|
| 내지도 표시 범위 | 내가 쓴 **모든 글** 표시(메인+비밀지도) + 출처 뱃지/필터. 내지도는 나만 보는 아카이브이므로 프라이버시 문제 없음 |
| 마커 없는 글(공지·담소) | **MVP 포함.** `post_type`으로 구분 |
| 초대 방식 | 초대 코드 + 딥링크 공유 |
| 멤버 제한 | 기본 100명 (지도별 컬럼, 설정으로 조정 가능. FCM 멀티캐스트 1콜 한도 500 이내) |
| 수익화(광고/판매/수수료) | **범위 제외.** 북극성 메모로만 유지 |

## 3. 데이터 모델 (unimal_board 스키마)

기존 코드 확인 결과 활용 포인트:
- `Board.location`이 이미 `Point?` nullable → 마커 없는 글 구조적으로 가능
- `BoardMember.fcmToken` 보유 → 멤버 푸시에 바로 사용
- `PostShow` enum 존재 → 비밀지도 글의 공개 범위는 지도 멤버십으로 결정되므로 PostShow와 별개 축

### 3.1 신규 테이블

```sql
-- 비밀지도 (엔티티명: SharedMap — map 모듈/MapBoard와 이름 충돌 회피)
CREATE TABLE shared_map (
    id            BIGSERIAL PRIMARY KEY,
    name          VARCHAR(50)  NOT NULL,          -- '광진구 런닝지도'
    description   VARCHAR(200),                   -- 방장 소개글 (탐색·참여 신청 시트에 노출, Flutter UX §3.7)
    cover_image   VARCHAR(500),                   -- 선택. 없으면 마커 썸네일로 대체
    owner_id      BIGINT NOT NULL REFERENCES board_member(id),  -- 방장
    invite_code   VARCHAR(10) UNIQUE NOT NULL,    -- 대소문자 없는 8자 랜덤 (재발급 가능)
    member_limit  INT NOT NULL DEFAULT 100,
    del           BOOLEAN NOT NULL DEFAULT FALSE,
    created_at    TIMESTAMP NOT NULL,
    updated_at    TIMESTAMP
);

CREATE TABLE shared_map_member (
    id             BIGSERIAL PRIMARY KEY,
    shared_map_id  BIGINT NOT NULL REFERENCES shared_map(id),
    member_id      BIGINT NOT NULL REFERENCES board_member(id),
    role           VARCHAR(15) NOT NULL DEFAULT 'MEMBER',   -- OWNER | MEMBER
    status         VARCHAR(15) NOT NULL DEFAULT 'ACTIVE',   -- ACTIVE | LEFT | KICKED
    last_seen_at   TIMESTAMP,                               -- 리스트 "새 글" 뱃지 계산용 (Flutter UX §3.1)
    joined_at      TIMESTAMP NOT NULL,
    UNIQUE (shared_map_id, member_id)
);
```

### 3.2 board 테이블 변경

```sql
ALTER TABLE board ADD COLUMN shared_map_id BIGINT REFERENCES shared_map(id);  -- NULL = 메인 지도
ALTER TABLE board ADD COLUMN post_type VARCHAR(15) NOT NULL DEFAULT 'STORY';  -- STORY | TALK | NOTICE
CREATE INDEX idx_board_shared_map ON board (shared_map_id) WHERE shared_map_id IS NOT NULL;
```

- `STORY`: 마커 글. `location` 필수 (서비스 레벨 검증)
- `TALK`: 담소. `location` NULL, 마커 없음
- `NOTICE`: 공지. 방장만 작성, 게시판 상단 고정
- **메인 지도 마커 쿼리에 `shared_map_id IS NULL` 조건 추가 필수** (기존 동작 보호 — 회귀 포인트 1순위)

## 4. 조회 스코프 규칙

| 화면 | 조건 |
|------|------|
| 메인 지도 마커 | `shared_map_id IS NULL` + 기존 조건(PostShow, 사진 필수, score 정렬) |
| 비밀지도 마커 | `shared_map_id = ?` AND `post_type = 'STORY'` + **요청자 멤버십 검증** |
| 비밀지도 게시판 | `shared_map_id = ?` AND `post_type IN ('TALK','NOTICE')`, NOTICE 상단 고정 + 최신순 페이징 |
| 내지도 | `email = 나` 전체 (shared_map join으로 출처 지도명 내려줌) |

비밀지도 마커 조회는 기존 PostGIS `ST_DWithin` 쿼리 재사용하되, 지도당 마커 수가 적으므로 **줌 반경 필터 없이 전체 마커 반환도 허용** (MVP 단순화, 클러스터링은 Flutter 기존 로직 재사용).

## 5. API (Gateway 경유, AccessTokenFilter)

ID는 기존 HashidsUtil로 인코딩해 노출.

| 메서드 | 경로 | 설명 | 권한 |
|--------|------|------|------|
| POST | `/board/shared-map` | 지도 생성 (생성자 = OWNER 자동 등록) | 로그인 |
| GET | `/board/shared-map/list` | 내가 속한 지도 목록 (이름, 멤버 수, 마커 수, 최근 글 시각, `hasNewPost`(last_seen_at 기준), 미니지도용 마커 좌표 목록) | 로그인 |
| GET | `/board/shared-map/{id}` | 지도 상세 + 멤버 목록 | 멤버 |
| PUT | `/board/shared-map/{id}` | 이름/설명/커버 수정 | OWNER |
| DELETE | `/board/shared-map/{id}` | 지도 폐쇄 (soft delete, 글은 유지하되 비노출) | OWNER |
| POST | `/board/shared-map/join` | `{ inviteCode }` 로 합류. 정원 초과/폐쇄/중복 검증 | 로그인 |
| DELETE | `/board/shared-map/{id}/leave` | 탈퇴 (OWNER는 위임 전 탈퇴 불가) | 멤버 |
| DELETE | `/board/shared-map/{id}/member/{memberId}` | 강퇴 | OWNER |
| POST | `/board/shared-map/{id}/invite-code` | 초대 코드 재발급 | OWNER |
| GET | `/board/shared-map/{id}/map/post` | 지도 마커 조회 | 멤버 |
| GET | `/board/shared-map/{id}/posts` | 게시판 목록 (TALK/NOTICE) | 멤버 |
| POST | `/board/post` (기존 확장) | `mapId`(옵션), `postType`(기본 STORY) 필드 추가 | 멤버 검증 |

글 수정/삭제/댓글/좋아요는 기존 엔드포인트 그대로 재사용 (board 단위 동작이므로 변경 최소).

## 6. 푸시 (Kafka → Notification)

- 비밀지도에 글 작성 → 기존 `board.postAppPushTopic` 페이로드에 `sharedMapId`, `mapName` 추가 (신규 토픽 대신 확장 — 컨슈머 분기 처리)
- Notification: 작성자 제외 ACTIVE 멤버의 fcmToken 수집 → **FCM 멀티캐스트 1콜** (100명 제한이라 500 한도 내)
- 푸시 문구: `[광진구 런닝지도] ○○님이 새 스토리를 남겼어요`
- 푸시 탭 → 해당 지도 화면 딥링크 랜딩
- 지도별 알림 mute는 2차

## 7. 초대 딥링크

- 스킴: `stomap://shared-map/join?code=XXXXXXXX` + Universal Link/App Link (`https://unimal.co.kr/m/{code}`)
- 미설치 유저: 웹 랜딩 → 스토어 유도 (링크 코드는 앱 첫 실행 시 수동 입력으로도 커버되므로 deferred deep link는 MVP 제외)
- 서버는 `join` API의 코드 검증만 담당. 코드 무차별 대입 방어: 재발급 가능 + 시도 횟수 제한(Redis)

## 8. 범위 제외 (2차 이후)

공개 지도 탐색/검색, 멤버 승인제(현재는 코드 있으면 즉시 합류), 지도별 알림 설정, OWNER 위임, 역할 세분화, 광고·판매·수수료 전반, 지도 아카이브/내보내기.

### 8.1 탐색·참여 신청 (2차 1순위 후보 — Flutter 시안 완료)

Flutter UX §3.7에 피그마 시안까지 완료된 상태. MVP(초대 코드)와 별개 트랙이며, 2차 진행 시 필요한 것:

- `shared_map.is_public BOOLEAN DEFAULT FALSE` — 공개 지도만 탐색 노출
- 참여 신청 테이블 또는 `shared_map_member.status`에 `PENDING`(신청) / `REJECTED`(거절) 추가 + 신청/수락/거절 API
- 신청 수락 시 신청자에게 FCM 푸시
- 핫 랭킹 산출: 주간 새 글 수 · 신규 멤버 수 가중 (배치 또는 Redis 카운터)
- `description`(방장 소개글)이 참여 신청 시트의 핵심 노출 필드가 됨 — MVP에서도 생성/수정 시 받아두는 것 권장

## 9. 구현 순서 (제안)

1. DDL + 엔티티/리포지토리 (SharedMap, SharedMapMember, Board 컬럼 추가)
2. **메인 지도 쿼리에 `shared_map_id IS NULL` 가드 + 기존 동작 회귀 테스트**
3. 지도 CRUD + 멤버십 API
4. 글 작성 확장(mapId/postType) + 지도 스코프 조회 API
5. 푸시 페이로드 확장 + Notification 멀티캐스트
6. Flutter 연동 (UX 스펙 별도 문서)
