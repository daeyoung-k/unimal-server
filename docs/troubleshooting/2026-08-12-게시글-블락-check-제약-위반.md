# 게시글 블락 시 board_show_check 제약 위반

## 증상

어드민에서 게시글 블락 실행 시:

```
ERROR: new row for relation "board" violates check constraint "board_show_check"
```

## 원인

Hibernate 6 는 `@Enumerated(EnumType.STRING)` 컬럼을 만들 때 **당시 enum 값들로
check 제약을 함께 생성**한다. `board.show` 의 `board_show_check` 는 `BLOCKED` 가
`PostShow` 에 추가되기 전에 만들어졌고, `ddl-auto: update` 는 컬럼 추가는 해도
**기존 check 제약은 갱신하지 않는다.** 그래서 DB 는 여전히 `BLOCKED` 를 거부한다.

enum 에 값을 추가할 때마다 같은 문제가 생길 수 있다 — `@Enumerated(STRING)` 컬럼의
enum 값이 늘면 이 문서를 떠올릴 것.

## 조치 (DB 에서 직접 실행)

현재 제약 확인:

```sql
SELECT pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conname = 'board_show_check';
```

제약 갱신:

```sql
ALTER TABLE unimal_board.board DROP CONSTRAINT board_show_check;
ALTER TABLE unimal_board.board ADD CONSTRAINT board_show_check
    CHECK (show IN ('PUBLIC', 'PRIVATE', 'FRIENDS', 'BLOCKED'));
```

## 함께 발견된 문제 — 어드민 ddl-auto 가 남의 스키마를 변경

같은 날 어드민 기동 로그에서:

```
alter table if exists unimal_board.board alter column email set data type varchar(255)
```

어드민의 읽기 전용 엔티티(`BoardPost` 등)에 length 지정이 없어, `ddl-auto: update` 가
board 소유 컬럼(varchar(50))을 255 로 넓혔다. 어드민이 손님인 스키마에 ALTER 를
날리는 구조 자체가 사고라, `AdminSchemaFilterProvider` 를 추가해 hbm2ddl 이
`unimal_admin` 스키마만 만지도록 제한했다 (`hibernate.hbm2ddl.schema_filter_provider`).

넓혀진 컬럼을 원복하려면 (선택 — 기능상 문제는 없다):

```sql
ALTER TABLE unimal_board.board ALTER COLUMN email TYPE varchar(50);
```

## 교훈

- `ddl-auto: update` 는 check 제약·컬럼 축소·제약 변경을 처리하지 못한다. enum 값
  추가 같은 변경은 수동 마이그레이션이 필요하다.
- 여러 서비스가 한 DB 를 스키마로 나눠 쓸 때, 다른 서비스 테이블을 매핑하는 모듈은
  hbm2ddl 범위를 자기 스키마로 제한해야 한다.
